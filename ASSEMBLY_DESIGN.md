# Module 10 implementation plan

This file records the design while prerequisite tests run. It is not a claim of implemented functionality.

Keep React/Node/Sharp/FFmpeg. Accept disk-streamed uploads: MP4/MOV/WebM independently per tile and format, six shared MP3/WAV/M4A/AAC narration files. Assign UUID file names, preserve original display names and hashes. FFprobe content rather than trusting extensions; decode to test readability. Ignore imported video audio for final assembly, with an explicit notice. Retain originals for editing export. Set practical upload/decoded-resolution/duration bounds and show them.

Normalize narration once to 48 kHz stereo PCM, count exact decoded samples from the resulting raw file (4 bytes per stereo s16 sample), preserve pauses and speech speed. Meter peaks and cap gain to avoid clipping; no aggressive compression. Visual timeline is integer 30 fps, 1600 audio samples/frame. Focus duration = ceil((lead-in samples + narration samples + lead-out samples)/1600). Defaults: narration starts exactly at focus segment, no overlap with camera clips. Lead-in/out controls mean silence within focus, never silently truncated narration. Missing audio requires a deliberate silent override with explicit duration. Missing Gemini video requires an explicit verified-PNG still fallback.

Imported clip segment controls select usable in/out points. Normalize with uniform FIT scale and padding to the independent target format, constant 30 fps, no source audio. Decode selected first/last displayed frames for seam metrics, preview images and comparison with the corresponding authoritative PNG. RGB/structural/alignment comparisons are quality indicators, not guaranteed equality or verified seamlessness. Show source dimensions and any aspect mismatch. First-frame PNGs remain unchanged.

Forward repetition is default. Render a three-cycle preview. Ping-pong is opt-in, avoids duplicate turn-around endpoint frames and warns about implausible reversed actions; constrain segment duration to bound FFmpeg reverse memory. Crossfade is optional: for base length L and overlap X, a periodic cycle can be formed by xfade two copies at L-X, then trim output frames X..L; prefix original frames 0..X before repeating the cycle. This makes the cycle period L-X and retains the initial supplied clip start. Do not combine ping-pong/crossfade unless explicitly supported and tested. Loop count uses effective period, final visual repetition trims to exact focus frame count while full narration remains.

Grid intro/intermediate/outro holds default 1.5/.5/2 seconds; allow per-tile intermediate override. Use Module 5's existing zoom-in and zoom-out clips and timings; narration changes must never trigger camera regeneration. Individual zoom-ins include placeholder holds, so preserve/document their full configured duration. Optional handoff mode none/still/crossfade adds explicit short segments before and after focus. Stills use the authoritative PNG; crossfades use decoded adjacent actual frames. Show bridge duration in timeline.

Build independent mobile/desktop timelines with intro → tile in → optional bridge in → emotional focus with narration → optional bridge out → tile out → intermediate grid (five times) → final grid. Every segment stores integer start/end frames and corresponding sample times, source IDs/checksums, loop period/count/in-out, bridge and transition references. Save settings atomically and use hashes for per-format freshness/cache reuse.

Render segments with safe FFmpeg argument arrays to temporary files; validate and atomically rename. Copy approved camera bytes into a private assembly run for a safe relative concat list. Produce final H.264/yuv420p/CFR30 video with AAC 48 kHz stereo. Use bounded process concurrency, no browser MediaRecorder and no whole-video Node buffers. Decode final outputs and verify frame count/duration, format and complete audio coverage. Preserve old successful files on failure/cancel; remove partial files. Support tile preview/render, low-resolution complete preview, each format, both, cancellation and retry. Reuse unchanged generated segments by hash.

Outputs: final_videos/lesson_mobile_9x16.mp4 and lesson_desktop_16x9.mp4; metadata/lesson_timeline.json, lesson_render_manifest.json, final_video_validation.json. Editing ZIP contains final MP4s, six original narrations, imported Gemini clips, 24 untouched original transitions, timeline and human-readable EDL. Finished MP4s are not native editable Clipchamp projects.

Tests use clearly labelled deterministic FFmpeg video and tone/silence fixtures; never label them real Gemini output or human narration. Test the 8.4-second sample rounding/repeat case; both output resolutions, full decoded frames, AAC samples, start offsets, unchanged camera hashes, missing assets, bridges, mismatches, restart, cancel/retry and package checksum coverage. Provide sample final videos from test inputs with honest provenance. Full Modules 8/9 acceptance remains blocked by the pending Module 8 specification; assembly itself depends on validated camera/frame assets, so its independent work can proceed after available regressions pass.

Reference: official FFmpeg filters documentation for trim/end_frame, setpts, concat, reverse, xfade, apad, atrim and adelay; FFprobe documentation for stream/frame timestamps. https://www.ffmpeg.org/ffmpeg-filters.html and https://ffmpeg.org/ffprobe.html
